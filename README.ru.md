# agent-kanban

**Локальный канбан-дашборд по вашим git-репозиториям + state-driven шаблоны работы для AI-агентов.**

[English](README.md) | Русский

Один HTML-файл показывает каждый локальный репозиторий карточкой: стадия, категория, последняя активность, коммиты, стек, незакоммиченные файлы, remote. Python-скрипт обновляет факты из git; описания, стадии и заметки — ваши. Без сети, без телеметрии, без аккаунтов.

**Требуется:** Python 3.8+, git, любой современный браузер. macOS — опционально (для запуска приложением).

## Что внутри

- `kanban/` — дашборд (один HTML-файл), updater, установщик
- `templates/` — SSOT-каркасы для агентской работы: `AGENTS.md`, `PROJECT_PLAN.md`, `TODO.md`, `CHANGELOG.md`, `WORKLOG.md`

## Установка — способ 1: мастер первого запуска (любая ОС)

```bash
git clone https://github.com/HlinorAI/agent-kanban.git
cd agent-kanban
python3 kanban/kanban-setup.py
```

Мастер сканирует обычные папки с кодом (`~/Documents`, `~/code`, `~/Developer`, …), показывает найденные git-репозитории, строит вашу личную доску в `~/kanban` и предлагает включить **«память агентов»**: кладёт `AGENTS.md` (опционально — полный набор SSOT-скелетов) в ваши репозитории, предварительно показывая, какие файлы будут созданы; существующие файлы никогда не перезаписываются. Без вашего подтверждения ничего не записывается.

Неинтерактивные флаги для скриптов: `--roots DIR[,DIR]`, `--target DIR`, `--yes`, `--seed`, `--seed-full`.

## Установка — способ 2: одна явная команда (любая ОС)

```bash
python3 kanban/kanban-init.py ~/code        # папка с вашими git-репозиториями (на глубину 1)
open ~/code/kanban.html                     # xdg-open на Linux
```

`kanban-init.py` пишет `kanban-projects.json` и `kanban.html` для указанной папки и заполняет факты по репозиториям.

Обновить факты в любой момент:

```bash
python3 kanban/kanban-update.py ~/kanban/kanban.html
```

## Установка — способ 3: приложение macOS

```bash
cd agent-kanban/kanban
./install-macos.sh --html ~/code/kanban.html                    # ставит ProjectKanban.app
./install-macos.sh --html ~/code/kanban.html --with-schedule    # + обновление при логине и ежедневно в 09:00
./uninstall-macos.sh                                            # полное удаление
```

Приложение открывает доску в отдельном окне Chrome (без адресной строки) и при каждом запуске обновляет факты в фоне — окно открывается мгновенно, свежие данные видны при следующем открытии или по ⌘R. Если доски ещё нет, первый запуск откроет мастер установки (способ 1) в окне Терминала. Также при первом запуске macOS один раз спросит доступ к файлам — это нужно для чтения ваших репозиториев, включая фоновые запуски по расписанию. Логи: `~/Library/Logs/kanban-app.log`.

**Если TCC-диалог не появился:** установщик специально делает ad-hoc-подпись, чтобы macOS могла показать запрос доступа. Если запрос так и не возник, а в `~/Library/Logs/kanban-app.log` ошибки `Operation not permitted` — выдайте доступ вручную: Системные настройки → Конфиденциальность и безопасность → **Полный доступ к диску** → **+** → **⌘⇧G** → `/Applications/ProjectKanban.app` → включить.

## Обновление по расписанию без приложения (Linux/macOS)

cron:

```cron
0 9 * * * cd /путь/к/agent-kanban && python3 kanban/kanban-update.py /путь/к/kanban.html >> /tmp/kanban-update.log 2>&1
```

или systemd user-таймер:

```ini
# ~/.config/systemd/user/kanban-update.service
[Unit]
Description=agent-kanban facts refresh

[Service]
Type=oneshot
ExecStart=/usr/bin/python3 /путь/к/agent-kanban/kanban/kanban-update.py /путь/к/kanban.html
```

```ini
# ~/.config/systemd/user/kanban-update.timer
[Unit]
Description=Refresh agent-kanban daily

[Timer]
OnCalendar=*-*-* 09:00:00
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
systemctl --user daemon-reload && systemctl --user enable --now kanban-update.timer
```

## Как править доску

- Язык интерфейса: `var LANG = 'en';` в начале скрипта внутри `kanban.html` — замените на `'ru'` для русского (стадии, фильтры, панель деталей переведены полностью).
- Карточки, категории, описания: редактируйте блок `var P = [...]` в `kanban.html`.
- Всё между `/* KB-DATA-BEGIN … KB-DATA-END */` — зона updater-а: он сначала делает `.bak` и отказывается писать, если guard-и обнаружили ручные данные в зоне.
- Репозитории из `kanban-projects.json`, которых нет в `P`, получают минимальные автокарточки (`auto_register: true`) — позже дополните их описаниями.
- Перемещения по стадиям и заметки хранятся в браузере (localStorage) и в файл не пишутся.
- Связанные репозитории можно объединить в семейства (блоки `GROUP`/`G`) и показывать как один продукт.

## Агентский набор

Скопируйте `templates/*.md` в корень своего проекта и укажите агенту (Claude Code, Codex, ZCode, Cursor, …) на `AGENTS.md` — большинство инструментов подхватывают его автоматически. Цикл, который он задаёт: читать состояние проекта перед работой (файлы, а не память чата), записывать состояние после каждого значимого шага, короткая спека в `.ai/specs/` до нетривиального кода, тесты как исполняемая спека, и никогда не заявлять «фичи нет», не проверив спеки, тесты и код.

## Приватность

Только локально: читает репозитории через `git` и файловую систему, не открывает сетевых соединений, показывает remote-URL с зачисткой данных доступа.

## Известные ограничения

- Очень большие папки репозиториев сканируются медленно (updater использует `git ls-files` и уважает `.gitignore`, но огромные репо всё же требуют времени).
- Одностраничной доске комфортно примерно до 100 карточек.
