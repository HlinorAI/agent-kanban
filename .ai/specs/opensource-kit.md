# Спека: agent-kanban (opensource kit)

Дата: 2026-11-05 · Статус: v0.1.0 локально

## Контракты

### kanban-projects.json
```json
{
  "kanban_html": "kanban.html",
  "auto_register": true,
  "projects": {
    "my-app": "~/code/my-app",
    "second": "~/code/second"
  }
}
```
- Пути с `~` раскрываются. `kanban_html` — путь относительно каталога конфига либо абсолютный.
- `auto_register` (по умолчанию true): репозиторий из `projects`, отсутствующий в ручном списке `P`, получает минимальную карточку `[id, <имя каталога>, 'product', 'solo', 'idea', '~/<path>', '', '']` — пользователь позже заполняет категорию/описание.

### Маркеры данных (не менять вручную)
`/* KB-DATA-BEGIN …` → `KB_UPDATED, ACT, START, EXTRA` → `… KB-DATA-END */` — перегенерируются updater-ом. Всё вне маркеров (включая P/GROUP/G/STAGES/CATS/MODES) — ручное; updater делает `.bak` и отказывается писать, если guard-строки (`var P = [` и др.) пропали.

### id
`id` = slug имени каталога репозитория (a-z0-9-), он же ключ в ACT/START/EXTRA и `p[0]` карточки.

## Критерии приёмки
1. `kanban-init.py <dir>` находит git-репо на глубине 1, пишет конфиг, создаёт `kanban.html` из шаблона, сразу запускает updater.
2. updater идемпотентен: повторный запуск без изменений — «Изменений нет», exit 0.
3. Каждому репо из конфига соответствует карточка (auto_register), данные: c/a/b/w/d/f/l/m/r/r7.
4. В файлах репо нет персональных строк прототипа (скан-лист в WORKLOG).
5. Установка на macOS: app открывает окно и запускает updater; uninstall убирает app и LaunchAgent полностью.
6. Всё работает без сети; python3.8+ и git — единственные зависимости.
